# 학습 API 연동 전 화면 미리보기

2026-10-11 기준. BE `develop`의 `docs/learning-api.md`, `docs/auth-fe-alignment.md`, `ContentDtos.java`, `ActivityDtos.java`를 기준으로 화면에 필요한 데이터와 흐름을 정리했다. 실제 학습 API 호출은 추가하지 않았다. 기존 인증·홈의 서버 연동과 챗봇 예시 동작은 그대로다.

## 확인할 화면

| 영역 | 확인할 기능 |
| --- | --- |
| 문법 | Java/Python/JavaScript, 현재 목록 검색, 북마크 필터, 학습별 난이도·상태 |
| 학습 상세 | 설명, 계층 목차, 본문·예제 코드, 이전/다음 목차, 마지막 위치 저장·이어하기, 완료·다시 학습, 연결된 문제 |
| 실무 | 캐시·DB·네트워크·로그 하위 분류, 검색·북마크, 공통 학습 상세 |
| 문제 | 언어·유형 필터, 제출한 문제 필터, 객관식·코드 설명·코드 작성의 개별 입력 |
| 제출 결과 | 제출 답안, 최근 제출 시각, 점수·통과 기준·피드백·해설, 재제출, 관련 학습 목차 이동 |

색상·글꼴·여백 토큰과 공통 카드·버튼·코드 박스·하단 메뉴 디자인은 기존 것을 사용한다. 고정된 오늘 목표/퍼센트, 3문항 묶음 결과, 예제 코드 문자열 비교 채점은 제거했다. API는 마지막 목차와 완료 시각을 제공하므로 진행 상태는 미시작·학습 중·완료로 표시한다.

목록 배치 보완: 문법·실무·문제 모두 소개 아래에 검색창과 필터 버튼을 같은 위치에 둔다. 언어·분류·유형·북마크/제출 여부는 챗봇과 같은 형태의 하단 선택창에서 고르고 적용한다. 닫기/바깥 영역 터치는 변경을 취소하며 초기화도 적용 전에는 목록을 바꾸지 않는다. 화면에는 선택 요약 한 줄만 표시한다. 학습 카드의 북마크는 상단 오른쪽에 배치하고 별도 하단 줄을 제거했다. 난이도와 학습 상태는 기존 카드 하단 안내 줄에 통합했다.

홈·문법·실무·문제 메인 화면의 상단은 `AppHomeHeader`를 공유한다. 홈의 중앙 로고(28px, 굵기 900), 프로필 아이콘·마이페이지 이동, 상단 간격과 목록 내 스크롤 방식을 사용한다. 상세 화면의 제목·뒤로가기는 유지한다.

문법·실무 상세는 공통 `TemplatePreviewScreen`에서 선택한 목차의 본문부터 보여준다. 목록 카드의 소개·난이도·상태·시각을 상단에 반복하지 않고, 상단 바의 목차 버튼으로 하단 선택창을 연다. 본문 카드는 메인 학습 카드와 같은 그림자를 사용하며 이전·다음 버튼을 좌우에 배치한다. 부모 목차에는 `children`의 제목을 표시하고 선택한 하위 예제로 이동한다. 연결 문제가 있는 학습의 마지막 목차에서는 ‘본문 읽기 완료’로 문제 안내 화면을 열되 학습 중 상태를 유지한다. 모든 문제를 맞히고 ‘학습 끝내기’로 저장한 시점에 완료된다. 연결 문제가 없는 학습은 마지막 목차의 ‘학습 완료’로 완료할 수 있다. 본문 아래에 문제 카드를 상시 표시하지 않는다.

연결 문제는 공통 `LearningPracticeScreen`으로 연다. 문법은 `/grammar-practice/{templateId}`, 실무는 `/learning-practice/{templateId}` 경로를 사용한다. 세 문제를 같은 페이지에서 모두 답한 후 ‘답 확인’을 한 번 누른다. 기존 문제별 미리보기 제출을 호출하고 모든 응답을 받은 뒤 결과를 함께 표시한다. 완료된 채점의 점수와 통과 기준으로 정답은 초록색, 오답은 빨간색으로 표시하며 글자·아이콘·해설도 함께 제공한다. 채점 대기는 정오답으로 판단하지 않는다. 제출 실패 시 입력을 보존하며 다시 시도할 수 있다. 일반 문제 목록에서는 기존처럼 선택한 문제를 한 개씩 연다. 문법·실무 확인 문제와 일반 문제는 `LearningQuestionCard`를 공유해 문제·답안·결과를 한 카드에 표시하고 해설은 ‘풀이 보기’로 펼친다. 일반 객관식 정답에는 ‘문제 끝내기’, 오답에는 ‘다시 풀기’, 코드·설명형 채점 대기에는 ‘새 답안 제출하기’를 제공한다. 실제 API 연결 시에도 문제별 제출 계약을 사용하며 일괄 제출 API가 있다고 가정하지 않는다.

## 더미 데이터와 상태

문법·실무 상세 및 문제 화면의 흰색 외곽선 버튼에는 그림자를 적용한다. 문제 채점 직후에는 정오답만 보여주고, 해설은 각 문제의 ‘풀이 보기/접기’로 펼치거나 접는다. 모든 문제가 채점 완료이며 통과 기준을 만족하면 ‘다시 풀기’ 대신 ‘학습 끝내기’를 표시하고 해당 언어의 문법 목록 또는 해당 분류의 실무 목록으로 이동한다. 오답이나 채점 대기가 있으면 다시 풀기를 유지한다.

- `lib/features/learning/data/learning_models.dart`: 화면에 쓰는 API 필드의 타입. 전체 응답 DTO나 JSON 역직렬화 구현은 아니다.
- `lib/features/learning/data/learning_preview_data.dart`: 기존 작성 콘텐츠를 템플릿·목차·문제 구조로 변환한 로컬 자료. ID는 미리보기 전용이며 서버 요청에 사용하면 안 된다.
- `lib/features/learning/presentation/learning_preview_store.dart`: 북마크, 학습 위치, 완료, 문제별 최근 제출을 메모리에 저장한다. 앱을 완전히 종료하거나 계정을 바꾸면 기록이 초기화된다. 계정 변경 전 시작한 요청은 반영하지 않는다.
- 문법·실무 상세는 본문을 처음 표시할 때 현재 목차를 저장하므로 첫 목차에서 나가도 학습 중으로 남는다. 목차 선택/이동도 위치를 저장하며 재진입하면 마지막 목차를 연다. 빈 목차나 없는 학습은 기록하지 않는다. 완료된 학습에서 목차를 이동해도 완료는 유지하며, 다시 학습하기로 해제한다.
- 객관식은 로컬 가짜 채점 테이블로 `COMPLETED/DB`와 100점 또는 0점을 반환한다. 정답 키는 화면용 문제 모델에 없다.
- 코드 작성·설명은 BE 현 구현처럼 `PENDING`, 점수·피드백 없음으로 남는다. 자동 AI 채점이나 코드 실행은 하지 않는다.
- 재제출은 문제별 최근 결과 한 건을 교체한다. 제출 이력 전체를 제공하는 것처럼 표시하지 않는다.
- 일반 문제에 재진입하면 답이 비어 있는 입력 화면을 먼저 보여주고, 최근 결과는 ‘최근 제출 결과 보기’로 연다. 문제 목록은 제출 전 흰색, 제출 기록이 있으면 연한 노란색, 정답을 맞힌 기록이 있으면 연한 초록색으로 표시한다. 제출 실패는 제출 기록으로 처리하지 않는다. 미리보기 세션 안에서 정답 이력을 별도로 기억하므로 복습 중 오답을 제출해도 초록색을 유지한다. 계정 변경·앱 완전 종료 시 초기화된다. 실제 API 연결 시 최신 제출 한 건만으로 과거 정답 이력을 복원할 수 없으므로 누적 정답 여부를 조회할 계약이 추가로 필요하다.
- `failNextAction`은 개발/테스트용 실패 주입이다. 로딩 실패 재시도, 북마크/학습 저장 실패, 답안 제출 실패 시 입력 보존을 확인할 수 있다.

미리보기에는 언어별 변수·조건문·반복문 학습이 있다. 반복문은 빈 목차 안내를 확인하는 사례다. 조건문에는 부모/자식 목차와 연결 문제가 있다. 실무는 언어가 없는 학습 사례다. `practical_quiz_preview_data.dart`에는 캐시·DB·네트워크·로그별 3문제씩 총 12개의 로컬 예시 문제가 있으며 서버 콘텐츠가 아니다. 캐시 첫 목차에는 첨부 자료 준비 안내가 있다.

## 다음 API 연결 때 확인할 계약

| 현재 화면 | 연결할 API |
| --- | --- |
| 언어·분류 | `GET /api/languages`, `GET /api/categories` |
| 학습 목록·상세 | `GET /api/templates`, `GET /api/templates/{id}` |
| 학습 위치·완료 | `GET/PUT /api/users/{userId}/progress/templates/{id}`, 필요 시 `GET /api/users/me/progress` |
| 북마크 | `GET /api/users/{userId}/bookmarks`, `PUT/DELETE /api/users/{userId}/bookmarks/templates/{id}` |
| 문제 목록·상세 | `GET /api/questions`, `GET /api/questions/{id}` |
| 제출·최근 결과 | `POST /api/questions/{id}/submissions`, `GET /api/questions/{id}/submissions/latest?userId=...` |

실제 연결은 기존 인증 Dio를 재사용하고 인증 사용자 ID를 사용한다. 카테고리/언어 ID는 서버 목록에서 매핑한다. 특히 실무 상위 카테고리 필터는 하위 카테고리를 자동 포함하지 않으므로 자식 분류도 조회해야 한다. 검색·유형·제출 여부 필터는 현재 불러온 목록에서 적용하는 FE 기능이다.

목차의 `body`, `exampleCode`, `children`을 그대로 표현한다. 개념/예제/출력값이라는 별도 API 필드는 만들지 않았다. 객관식 `choiceOptions`는 BE에서 JSON 배열까지만 정의되어 있어 현재 `{key, text}` 형태를 내부 미리보기 규칙으로 사용하며 실제 요소 형식은 합의가 필요하다.

미디어는 `objectKey`만 있고 공개 URL/다운로드 계약이 없다. 해당 값을 URL로 요청하지 않으며 첨부 자료 안내만 표시한다. 실제 이미지 표시·업로드는 URL 계약 후 연결한다. `criteriaResults`의 내부 구조와 `aiModelVersion`을 활용한 AI 상세 결과는 AI 계약이 결정된 후 추가한다. 챗봇 API와 관리자 화면은 이번 범위에 포함하지 않았다.

## 경로와 검증

- 문법: `/grammar/{java|python|javascript}/chapters/{templateId}`
- 문법 학습 확인 문제: `/grammar-practice/{templateId}`
- 실무 학습 확인 문제: `/learning-practice/{templateId}`
- 실무: `/practical/{categoryId}/templates/{templateId}`
- 학습 목차 지정: 위 상세 주소의 `?section={sectionId}`
- 문제: `/problems/{questionId}`

기존 `conditions/example/quiz`, `cache/chapters/basics`, `java-basics` 등 샘플 전용 상세 주소는 새 ID 경로로 교체했다. 인증·홈·마이페이지·챗봇 경로는 유지한다.

검증은 상태 단위 테스트, 학습·문제 위젯 테스트, 기존 인증/홈 회귀 테스트, 320px/큰 글씨/가로 화면의 학습·결과·챗봇 레이아웃 테스트로 구성한다. 명령은 `flutter analyze`, `flutter test`다.

로컬 검증 결과: 상단 바 통일 시점 전체 테스트 148개 통과. 문법 본문·일괄 답 확인 개편은 목차 이동·완료·정오답 색상·실패 재시도·실무 회귀·화면 크기별 배치 관련 테스트 28개와 정적 분석을 통과했다. Android debug APK 빌드도 성공했다. 학습 API 요청이나 BE 파일·DB 변경은 추가하지 않았다.

후속 풀이 펼치기·학습 끝내기 변경은 언어별 목록 복귀 및 큰 글씨 배치를 포함한 관련 테스트 16개를 통과했다.

상태 표시 보완: 문법·실무 목록의 학습 중 카드는 연한 노란색 배경과 ‘학습 중 · 이어하기’, 완료 카드는 연한 초록색 배경·체크와 ‘학습 완료 · 복습하기’를 표시한다. 카드의 흰색 본문 영역만 상태 색으로 바꾸며 기존 테두리·그림자·하단 안내 영역·배치·크기는 유지한다. ‘학습 끝내기’는 완료 상태 저장이 성공한 뒤 해당 언어 목록으로 이동하며, 저장 실패 시 결과를 유지하고 재시도할 수 있다. 다시 학습하기로 완료를 해제하면 목록 표시도 학습 중으로 돌아간다. 본문만 읽은 경우의 완료 방지, 중간 이탈 후 이어하기 및 회귀 테스트 31개를 통과했으며, 후속 배경색 변경은 관련 테스트 19개로 검증한다. 기록은 기존 미리보기 저장소의 메모리 범위에서만 유지된다.

문법·실무 상세 및 문제 카드 통일 후 전체 테스트 163개 통과. 상단 상세 바·목차 선택창·본문 그림자·연결 문제의 일괄 답 확인·풀이 펼치기·완료 상태·분류별 목록 복귀를 공통으로 사용한다. 실제 학습 API 연결은 아직 추가하지 않았다.
